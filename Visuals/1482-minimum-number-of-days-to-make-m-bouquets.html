Minimum Number of Days to Make m Bouquets / visualized

The array is never searched. What gets searched is the day — every candidate answer between the first bloom and the last. bouquets(day) is the only thing that ever touches bloomDay: it walks left to right, counts runs of already-bloomed flowers, and banks a bouquet every time a run reaches k. Waiting longer never un-blooms a flower, so that count is monotone non-decreasing in day — and a monotone predicate is exactly what binary search needs.

Choosing lo and hi — the step people get wrong

lo = min(bloomDay): before the first flower opens nothing can be picked, so no earlier day is worth testing. hi = max(bloomDay): on that day every flower is open, which is the most generous the garden ever gets — if it fails there it fails forever.

  • The range must be drawn from the values, not the indices. Days are the answer space; the array is data.
  • Set hi below max(bloomDay) and a reachable answer can fall outside the range — the search then returns a day the predicate never accepted. Silently wrong.
  • Overshooting hi only costs iterations, never correctness. When unsure, overshoot.

The guard comes first. m · k flowers must physically exist, so if m · k > n the answer is -1 and no amount of waiting helps. Check it before the search: with an impossible target every candidate is infeasible, the range collapses onto hi, and the search would happily hand back the last day as if it worked.

This is the G shape: minimise the maximum — the smallest day that still works. Feasible means “late enough”, so feasible pulls the ceiling down (hi = mid) and the answer is the smallest feasible candidate: lo when the range closes.

O(n · log(max − min)) time · O(1) space  ·  bouquets(day) never decreases as day grows — that is the entire licence to binary search the calendar.
