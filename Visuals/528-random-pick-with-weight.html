Random Pick with Weight / visualized

Pick index i with probability proportional to w[i]. The trick is to stop thinking about probability and start thinking about length: lay the weights end to end along a number line, throw a uniform dart at it, and report whose segment it landed in. Finding the segment is a binary search over prefix sums.

The dart is an input here, not a random draw — a visualizer whose frames change under you is not a visualizer. In the real solution this is rand() % total; every value it can take is reachable from this box.

Why a uniform dart gives weighted odds

the segmentsIndex i owns the half-open interval [P[i-1], P[i]), whose width is exactly w[i]. The intervals do not overlap and together they cover [0, total) with no gaps — that is just what a running total is.

the dartA uniform integer in [0, total) lands in interval i with probability width / total = w[i] / total. That is the whole proof. No sampling, no approximation, no law of large numbers — it is exact for every single draw.

the searchLanding in [P[i-1], P[i]) means target < P[i] and target ≥ P[i-1]. So the answer is the first index whose prefix sum is strictly greater than the target — a leftmost-true search, not an equality search. There is always such an index, because target < total = P[n-1].

the boundary that catches people>, not ≥. With ≥, a target sitting exactly on a boundary is handed to the wrong index — and worse, an index whose weight is 0 becomes reachable, which it must never be. Zero-weight indices own an empty interval and can never be picked. Try weights with a 0 in them and step through the boundary case.

O(n) to build · O(log n) per pick · O(n) space  ·  the search runs over a derived array, and the thing being searched for is a position on a line rather than a value in the input.
