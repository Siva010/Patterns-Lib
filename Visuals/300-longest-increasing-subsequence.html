Binary Search — search inside a maintained array LeetCode 300

Longest Increasing Subsequence / visualized

One left-to-right pass over the input, maintaining a second array tails where tails[j] is the smallest value that can end an increasing subsequence of length j+1. tails is sorted by construction, so each new value is placed by binary search — overwrite the first tail ≥ it, or append if there is none. The answer is tails.length. Its length. Not its contents.

The one thing to take away: tails is not the answer subsequence. Its length is exactly right, always. Its contents are usually not an increasing subsequence of the input at all — frequently not even a subsequence of the input, in any order. Run the 1, 3, 5, 2 chip: it ends with tails = [1, 2, 5], and the input has no 5 after its only 2. The length 3 is right; the array is wreckage. The reason is the overwrite on line 11: writing x into slot j claims only that some increasing run of length j+1 ends at x at this moment. The slots to its left may already have been overwritten by values that arrived later, so the array is a mixture of eras. Only the high-water mark — the length — is a statement about the whole prefix. Recovering the actual subsequence needs a parent pointer per index, which is why the reconstruction shown below is done with the O(n²) DP instead.

why binary searchThe naive DP asks, for each i, “which earlier j has nums[j] < nums[i] and the best dp[j]?” — an O(n) scan, O(n²) overall. Patience sorting replaces that scan with a lookup into a sorted array, and a lookup into a sorted array is a binary search. That is the entire n² → n log n step, and it is the log factor you can see on screen.

why tails stays sortedSlot j is the best tail for length j+1; a longer run needs a strictly larger tail to keep going, so tails[0] < tails[1] < … holds after every write. Overwriting the first tail ≥ x with x preserves it: the neighbour to the left is < x (that is why the search moved past it) and the neighbour to the right was already ≥ the value being replaced.

the one-character variantStrictly increasing uses lower_bound — the first tail ≥ x — so an equal value overwrites rather than extends, and duplicates cannot lengthen a run. For the non-decreasing variant, switch to upper_bound: change the test on line 8 from tails[mid] < x to tails[mid] <= x. Equal values then land past the run of equals and append, which is exactly what non-decreasing means. Nothing else in the method changes.

O(n log n) time · O(n) space  ·  the binary search is not over the input — it is over an array the algorithm is building, whose height is the answer and whose contents are scaffolding.
