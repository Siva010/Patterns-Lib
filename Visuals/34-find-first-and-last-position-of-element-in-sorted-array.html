Find First and Last Position of Element in Sorted Array / visualized

There is no special “find the range” search. There is one primitive — lowerBound(key), the first index whose value is ≥ key — and you run it twice: once for target, once for target + 1. The answer is [ lb(target), lb(target+1) − 1 ]. Upper bound is not a second algorithm; it is lower bound with the key nudged by one. The interval is half-open: lo is inside, hi is not, and that single fact is what makes hi = mid correct where hi = mid - 1 would loop forever or skip the answer.

Half-open [lo, hi) — the invariant, spelled out

lowerBound never asks “did I find it?”. It maintains a partition of the whole index space 0 .. n into three parts and shrinks the middle one to nothing:

  • every index < lo is known to hold a value < key;
  • every index ≥ hi is known to hold a value ≥ key (or is the past-the-end slot n);
  • [lo, hi) is the undetermined part — the teal bracket on the tape.

So when nums[mid] ≥ key, mid qualifies and must remain reachable as an answer: hi = mid moves the exclusive ceiling onto it, keeping it as the best-known boundary while dropping everything to its right. hi = mid - 1 would throw the answer away. When the bracket empties, lo == hi and that index is the boundary — no separate found/not-found test inside the loop.

Why hi starts at n, not n-1: “no element is ≥ key” is a real answer, and its name is n. With an inclusive hi = n-1 you have nowhere to put that answer, which is why inclusive versions of this search need an extra post-loop special case.

Upper bound for free: the first index past the block of target is exactly the first index whose value is ≥ target + 1. On integer data that is lb(target+1). Memorise lower bound; derive everything else. First occurrence = lb(target), last occurrence = lb(target+1) - 1, count = lb(target+1) - lb(target).

O(log n) time · O(1) space — two independent binary searches, so 2 · log₂n probes  ·  hi is exclusive; hi = mid keeps the candidate, lo = mid + 1 discards it. Those two lines are the entire pattern.
